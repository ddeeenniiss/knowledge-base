PHP (PHP: Hypertext-Präprozessor)

PHP ist eine serverseitige Skriptsprache zur Erstellung dynamischer und interaktiver Webseiten. Der Code wird auf dem Server ausgeführt, beim Browser kommt nur das Ergebnis (HTML, JSON, eine Datei) an. Im Quellcode der Seite ist von PHP nichts mehr zu sehen.

PHP ist eine interpretierte Sprache mit dynamischer Typisierung. Seit PHP 7 ist sie deutlich schneller geworden, seit PHP 8 kommen echte Typdeklarationen, Enums, match und der JIT-Compiler hinzu. Aktuell gepflegt werden die 8.x-Versionen; alles unter 8.1 erhält keine Sicherheitsupdates mehr und sollte nicht mehr produktiv laufen.

Wie PHP ausgeführt wird (SAPI)

SAPI steht für "Server API" und beschreibt, auf welchem Weg PHP angesprochen wird. Wichtig zu wissen, weil jede SAPI ihre eigene php.ini verwenden kann.

  • CLI – PHP auf der Kommandozeile, z.B. php script.php oder Composer-Befehle.
  • Built-in Webserver – zum Entwickeln: php -S localhost:8000 im Projektordner. Damit laufen auch die Formular-Beispiele dieser Knowledge Base.
  • PHP-FPM (FastCGI Process Manager) – Standard auf modernen Servern, läuft als eigener Prozess hinter nginx oder Apache.
  • mod_php – PHP als Apache-Modul. Älter, nur hier funktionieren php_value-Einträge in der .htaccess.

Syntax-Grundlagen

PHP verwendet <?php ... ?> Tags, um PHP-Code in HTML-Dateien einzubetten.

Mit <?php echo 'Ausgabetext'; ?> lassen sich Inhalte ausgeben. Idealerweise lässt sich <?= nutzen, das eine Kurzform für <?php echo darstellt.

In Dateien, die nur PHP enthalten (Klassen, Konfiguration), lässt man das schließende ?> absichtlich weg. So kann kein versehentliches Leerzeichen hinter dem Tag die Ausgabe starten – was sonst zum Klassiker "headers already sent" führt.

Schlüsselwörter, Klassen und Funktionen sind nicht case-sensitive, echo ist also auch ECHO. Variablennamen sind dagegen case-sensitive: $name und $Name sind zwei verschiedene Variablen.

Jede Anweisung endet mit einem Semikolon. Nur bei der letzten Anweisung vor einem schließenden ?> ist es optional.

Kommentare

Einzeilig: // oder #

Mehrzeilig: /* ... */

Dokumentationskommentare (DocBlocks) beginnen mit /** und werden von IDEs für Autovervollständigung ausgelesen. 

/**
 * Begrüßt einen Benutzer.
 *
 * @param string $name
 * @return string
 */

Variablen

Variablen in PHP beginnen mit einem $-Zeichen, gefolgt vom Variablennamen. Die Typen sind dabei dynamisch, daher kein integer, string, float etc. bei der Deklaration notwendig – eine Variable entsteht durch die erste Zuweisung. 

$name = "John";
$zahl = 42;

Erlaubt sind Buchstaben, Ziffern und Unterstriche, das erste Zeichen darf keine Ziffer sein (gültig: $name, $_id, $preis2 – ungültig: $2preis, $mein-name). Variablennamen sind case-sensitive: $name und $Name sind zwei verschiedene Variablen. Konvention in PHP ist camelCase ($firstName), bei Klassen PascalCase und bei Konstanten GROSSSCHREIBUNG.

Existenz prüfen und löschen

Der Zugriff auf eine nicht existierende Variable erzeugt seit PHP 8 eine Warning ("Undefined variable") und liefert null. Deshalb vor dem Zugriff prüfen oder mit ?? einen Standardwert setzen. 

isset($name);        // existiert und ist nicht null
empty($name);        // existiert nicht oder ist "falsy"
$name = $name ?? 'Gast';
unset($name);        // Variable entfernen

Zuweisung: Wert oder Referenz

Standardmäßig wird bei einer Zuweisung der Wert kopiert. Mit & entsteht dagegen eine Referenz, beide Namen zeigen dann auf denselben Inhalt. Objekte sind die Ausnahme: dort zeigen beide Variablen immer auf dieselbe Instanz. 

$a = 5;
$b = $a;      // Kopie
$b = 10;      // $a bleibt 5

$c = &$a;     // Referenz
$c = 10;      // $a ist jetzt auch 10

Gültigkeitsbereich (Scope)

Variablen aus dem Hauptskript sind in einer Funktion nicht sichtbar – PHP kennt keinen "Durchgriff" von außen nach innen. Das ist der häufigste Anfängerfehler. Umgekehrt sind Variablen aus einer Funktion außerhalb ebenfalls nicht verfügbar. 

$x = 5;

function myTest() {
    echo $x; // Warning: Undefined variable $x
}

function besser(int $x) {
    echo $x; // richtig: als Parameter übergeben
}
besser($x);

Mit global $x; oder über $GLOBALS['x'] ließe sich die äußere Variable holen, das gilt aber als schlechter Stil, weil die Abhängigkeit nicht mehr an der Funktionssignatur erkennbar ist. Parameter und Rückgabewerte sind der saubere Weg.

static innerhalb einer Funktion behält den Wert über mehrere Aufrufe hinweg, ohne ihn global zu machen: 

function zaehler(): int {
    static $count = 0;
    return ++$count;
}
zaehler(); // 1
zaehler(); // 2

Eine Ausnahme von der Scope-Regel sind die superglobalen Variablen ($_POST, $_SERVER, $_SESSION usw.) – sie sind überall ohne global verfügbar.

In einer Closure werden äußere Variablen mit use importiert, eine Arrow Function (fn) übernimmt sie automatisch. Eingebundene Dateien per include/require teilen dagegen den Scope der einbindenden Stelle.

Variable Variablen

Mit $$ lässt sich ein Variablenname aus dem Inhalt einer anderen Variablen bilden. Funktioniert, führt aber schnell zu unlesbarem Code – ein Array ist in solchen Fällen fast immer die bessere Lösung. 

$feld = 'name';
$$feld = 'John';   // erzeugt $name
echo $name;        // "John"

Datentypen

PHP ist dynamisch typisiert: der Typ einer Variablen ergibt sich aus dem zugewiesenen Wert und kann sich jederzeit ändern. Man deklariert ihn also nicht, sollte ihn aber kennen – viele Fehler entstehen genau dort, wo PHP unerwartet umwandelt. 

$wert = "42";   // string
$wert = 42;     // int
$wert = 42.5;   // float
$wert = true;   // bool
$wert = null;   // null

Skalare Typen

  • string – Text: "Hallo". Beliebig lang, intern eine Folge von Bytes. Umlaute belegen in UTF-8 mehrere Bytes, daher für Längen und Teilstrings die mb_*-Funktionen nutzen.
  • int – Ganzzahl: 42, -7, 0. Auf 64-Bit-Systemen bis PHP_INT_MAX (ca. 9,2 Billiarden). Bei Überschreitung wird daraus automatisch ein float.
  • float – Kommazahl: 3.14 (Punkt, nicht Komma!). Da Fließkommazahlen binär gespeichert werden, ist 0.1 + 0.2 === 0.3 false. Deshalb Geldbeträge nie als float rechnen, sondern in Cent als int – oder mit einer Toleranz vergleichen: abs($a - $b) < 0.00001.
  • bool – true / false. In der Ausgabe wird true zu "1" und false zu einem leeren String, daher zum Prüfen var_dump() nutzen.

Zusammengesetzte Typen

  • array – Liste oder Schlüssel-Wert-Paare, intern immer eine geordnete Map.
  • object – Instanz einer Klasse. Objekte werden bei der Zuweisung nicht kopiert, beide Variablen zeigen auf dieselbe Instanz (Kopie mit clone).
  • callable – eine aufrufbare Funktion, Closure oder Methode, typisch als Callback für array_map().
  • iterable – alles, was mit foreach durchlaufen werden kann: array oder Traversable.
  • resource – Verweis auf eine externe Ressource, z.B. ein offenes Dateihandle aus fopen().

null

null bedeutet "kein Wert" und ist der Typ einer Variablen, die noch nichts zugewiesen bekommen hat oder mit unset() geleert wurde. Wichtig ist der Unterschied zu einem leeren String oder 0 – das sind vorhandene Werte. 

$a = null;
var_dump(isset($a));        // false – null gilt als "nicht gesetzt"
var_dump($a === null);      // true
var_dump(is_null($a));      // true
var_dump($a ?? 'Standard'); // "Standard"

Typ prüfen und ausgeben

var_dump($wert) zeigt Typ und Wert und ist damit das wichtigste Debugging-Werkzeug. print_r($array) gibt Arrays lesbar aus (mit true als 2. Parameter als String zurück), gettype() liefert den Typnamen. 

var_dump("5");    // string(1) "5"
var_dump(5);      // int(5)
var_dump(5.0);    // float(5)
var_dump(true);   // bool(true)
var_dump([1, 2]); // array(2) { [0]=> int(1) [1]=> int(2) }

Gezielte Prüfungen: is_string(), is_int(), is_float(), is_bool(), is_array(), is_object(), is_null(), is_numeric() (Zahl oder numerischer String), is_callable().

Typumwandlung (Casting)

PHP wandelt Typen bei Bedarf automatisch um – "3" + 4 ergibt 7. Explizit geht es per Cast in Klammern oder über Funktionen. 

(int) "42abc"     // 42  – schneidet ab der ersten Nicht-Ziffer ab
(int) "abc"       // 0
(float) "3,5"     // 3   – Achtung: Komma wird nicht erkannt
(string) 42       // "42"
(bool) "0"        // false
(array) "Hallo"   // ["Hallo"]

intval($wert); floatval($wert); strval($wert); boolval($wert);
settype($wert, 'int');  // ändert die Variable selbst

Da ein Cast stillschweigend 0 liefert, ist zur Prüfung von Benutzereingaben filter_var() besser geeignet – es gibt bei ungültigen Werten false zurück: 

$seite = filter_var($_GET['seite'] ?? '', FILTER_VALIDATE_INT);
if ($seite === false) {
    $seite = 1;
}

Falsy-Werte

Als false gelten: false, 0, 0.0, "" (leerer String), "0", leeres Array und null. Achtung: der String "0" ist falsy, der String "false" dagegen truthy – ebenso wie "0.0" und " " (Leerzeichen).

empty($var) prüft auf falsy, ohne bei nicht existierenden Variablen eine Warnung auszulösen. isset($var) prüft, ob die Variable existiert und nicht null ist. Bei einer Zahl, die 0 sein darf, ist empty() daher die falsche Prüfung – dort gehört isset() oder ein Vergleich mit !== ''.

Vergleiche: == und ===

== vergleicht nur den Wert und wandelt dabei Typen um, === vergleicht Wert und Typ. Seit PHP 8 ist der lockere Vergleich deutlich weniger überraschend, trotzdem gilt: immer === verwenden. 

0 == "0"       // true
"1" === 1      // false – unterschiedlicher Typ
null == false  // true
0 == "abc"     // false (ab PHP 8; vorher true!)
"10" == "1e1"  // true – beide werden als Zahl gelesen

Typdeklarationen

Auch wenn Variablen selbst keinen festen Typ haben, lassen sich Parameter, Rückgabewerte und Klasseneigenschaften typisieren. Das macht den Code selbsterklärend und Fehler fallen sofort auf. 

function teile(int $a, int $b): float
{
    return $a / $b;
}

function finde(int $id): ?User      // User oder null
{
    return $this->users[$id] ?? null;
}

function verarbeite(int|string $id): void   // Union Type, ab PHP 8
{
    // void = gibt nichts zurück
}

class Produkt
{
    public string $name = '';
    public ?float $preis = null;    // typisierte Eigenschaft, ab PHP 7.4
}

Strict Types

Mit declare(strict_types=1); als erster Anweisung einer Datei akzeptiert PHP bei Typdeklarationen keine stillen Umwandlungen mehr – aus "5" wird dann nicht automatisch 5, sondern ein TypeError. Empfohlen für jede neue Datei, da Fehler früh auffallen. 

<?php
declare(strict_types=1);

teile("10", 2);  // ohne strict_types: funktioniert
                 // mit strict_types:  TypeError

Strings

Der entscheidende Unterschied: in doppelten Anführungszeichen werden Variablen und Escape-Sequenzen wie \n ausgewertet, in einfachen nicht. 

$name = "John";
echo "Hallo $name";     // Hallo John
echo 'Hallo $name';     // Hallo $name
echo "Hallo {$user['name']}"; // geschweifte Klammern bei Array-/Objektzugriff

Variablen verketten

Um Strings in PHP zu verketten, verwendet man den Punkt (.) als Verknüpfungsoperator. .= hängt an eine bestehende Variable an. 

echo $name . " " . $lastname;

$html = '';
$html .= '<li>Eintrag</li>';

Heredoc und Nowdoc

Für mehrzeilige Texte, z.B. HTML- oder Mail-Templates. Heredoc (<<<HTML) wertet Variablen aus, Nowdoc (<<<'HTML') nicht. 

$text = <<<HTML
<h1>Hallo $name</h1>
<p>Willkommen!</p>
HTML;

Wichtige String-Funktionen

  • strlen() – Länge in Bytes, mb_strlen() für Umlaute/UTF-8
  • trim() / ltrim() / rtrim() – Leerzeichen entfernen
  • strtolower() / strtoupper() / ucfirst() / ucwords()
  • str_replace($suche, $ersatz, $text)
  • substr($text, 0, 10) – Teilstring
  • strpos($text, $suche) – Position, gibt false zurück wenn nicht gefunden (daher immer mit !== false prüfen)
  • str_contains() / str_starts_with() / str_ends_with() – ab PHP 8, deutlich lesbarer als strpos
  • explode(",", $text) – String zu Array, implode(", ", $array) – Array zu String
  • sprintf("%s hat %d Punkte", $name, $punkte) – formatierte Ausgabe, number_format() für Tausenderpunkte
  • nl2br() – Zeilenumbrüche zu <br>
  • htmlspecialchars() – Pflicht bei jeder Ausgabe von Benutzereingaben (siehe Sicherheit)

Bei Umlauten und Sonderzeichen immer die mb_*-Varianten verwenden (mb_strlen, mb_substr, mb_strtolower), da ein UTF-8-Umlaut aus zwei Bytes besteht.

Konstanten

Eine Konstante ist ein Wert, der einmal festgelegt wird und sich danach nicht mehr ändern lässt. Im Unterschied zu Variablen steht kein $ davor, und sie sind automatisch in jedem Gültigkeitsbereich verfügbar – also auch innerhalb von Funktionen, ohne global. Konvention ist GROSSSCHREIBUNG mit Unterstrichen.

Typischer Einsatz: Konfigurationswerte, Pfade, Grenzwerte und feste Statuswerte, die sich zur Laufzeit nicht ändern dürfen. 

define('SITE_NAME', 'Knowledge Base');
const MAX_UPLOAD = 5;

echo SITE_NAME;
echo MAX_UPLOAD;

define() oder const?

  • const – wird beim Kompilieren ausgewertet, muss daher auf oberster Ebene stehen (nicht in if-Blöcken) und benötigt einen festen Wert. Innerhalb von Klassen ist const die einzige Möglichkeit. Etwas schneller und von IDEs besser erkannt – im Zweifel die richtige Wahl.
  • define() – wird zur Laufzeit ausgeführt und kann deshalb bedingt oder mit berechneten Werten verwendet werden. Nötig, wenn der Name selbst erst zur Laufzeit feststeht. 
// nur mit define() möglich
if (!defined('DEBUG')) {
    define('DEBUG', $_SERVER['HTTP_HOST'] === 'localhost:8000');
}

defined('NAME') prüft, ob eine Konstante existiert, und verhindert den Fehler "Constant already defined". constant('NAME') liest eine Konstante über einen Variablennamen aus.

Konstanten in Klassen und Enums

In Klassen und Interfaces werden Konstanten mit const definiert und über :: angesprochen. Sie können public, protected oder private sein. 

class User
{
    public const ROLE_ADMIN  = 'admin';
    public const ROLE_EDITOR = 'editor';
}

echo User::ROLE_ADMIN;   // von außen
// innerhalb der Klasse: self::ROLE_ADMIN oder static::ROLE_ADMIN

Für eine feste Menge zusammengehöriger Werte sind Enums (ab PHP 8.1) allerdings die bessere Lösung, da dort ungültige Werte gar nicht möglich sind.

Vordefinierte und magische Konstanten

PHP bringt selbst eine Reihe von Konstanten mit:

  • PHP_VERSION, PHP_OS, PHP_INT_MAX, PHP_FLOAT_EPSILON
  • PHP_EOL – betriebssystemgerechter Zeilenumbruch
  • DIRECTORY_SEPARATOR – / bzw. \ je nach System
  • E_ALL, E_WARNING – Fehlerstufen für error_reporting()
  • UPLOAD_ERR_OK, PASSWORD_DEFAULT, JSON_THROW_ON_ERROR – Konstanten einzelner Erweiterungen

Die magischen Konstanten (doppelter Unterstrich) ändern ihren Wert je nach Position im Code und werden nicht mit define gesetzt:

  • __DIR__ – Ordner der aktuellen Datei, die zuverlässige Basis für include-Pfade
  • __FILE__ – absoluter Pfad der aktuellen Datei
  • __LINE__ – aktuelle Zeilennummer
  • __CLASS__, __FUNCTION__, __METHOD__, __NAMESPACE__
require_once __DIR__ . '/config.php';   // bricht nicht, egal von wo eingebunden
error_log(__FILE__ . ':' . __LINE__ . ' – Wert: ' . $wert);

Unterschied zur Variablen in einem Satz: Variablen haben ein $, sind veränderbar und an einen Gültigkeitsbereich gebunden – Konstanten haben kein $, sind unveränderbar und überall sichtbar.

Operatoren

  • Arithmetisch: + - * / % (Modulo, Rest) ** (Potenz)
  • Zuweisung: = += -= *= /= .= ??=
  • Inkrement: $i++ / ++$i / $i--
  • Vergleich: == != < > <= >= und === / !== wenn exakt gleicher Typ und Wert verglichen werden sollen
  • Spaceship: <=> gibt -1, 0 oder 1 zurück, praktisch für usort()
  • Logisch: && (und), || (oder), ! (nicht), xor
  • Null-Coalescing: ?? – nimmt den rechten Wert, wenn der linke nicht existiert oder null ist
  • Ternär: $a ? $b : $c, Kurzform $a ?: $c
  • Nullsafe: $user?->getAddress()?->city – bricht ab, statt bei null einen Fehler zu werfen

Faustregel: immer === verwenden. Der ==-Vergleich wandelt Typen um und führt zu Überraschungen. ?? ist der sichere Weg, um Formular- oder Konfigurationswerte mit Standardwert zu lesen: 

$name = $_POST['name'] ?? '';
$limit = $config['limit'] ?? 10;
$count ??= 0; // setzt nur, wenn noch nicht gesetzt

Bedingungen

Bedingungen in PHP werden mit if, elseif und else abgefragt. 

if ($age >= 18) {
    echo "Du bist volljährig";
} elseif ($age > 0) {
    echo "Du bist minderjährig";
} else {
    echo "Ungültiges Alter";
}

In Templates ist die alternative Syntax lesbarer, weil sich HTML dazwischen sauber einfügen lässt: 

<?php if ($user): ?>
    <p>Hallo <?= htmlspecialchars($user['name']) ?></p>
<?php else: ?>
    <a href="/login">Anmelden</a>
<?php endif; ?>

switch und match

switch vergleicht locker (==) und braucht break, sonst läuft der Code in den nächsten Fall weiter. 

switch ($rolle) {
    case 'admin':
        $rechte = 'alle';
        break;
    case 'redakteur':
        $rechte = 'bearbeiten';
        break;
    default:
        $rechte = 'lesen';
}

match (ab PHP 8) ist ein Ausdruck, vergleicht strikt (===), braucht kein break und gibt direkt einen Wert zurück. In der Regel die bessere Wahl. 

$rechte = match($rolle) {
    'admin'               => 'alle',
    'redakteur', 'autor'  => 'bearbeiten',
    default               => 'lesen',
};

Schleifen

Schleifen in PHP können mit for, while, do-while und foreach erstellt werden. 

for ($i = 0; $i < 10; $i++) {
    echo $i;
}

while ($zeile = $stmt->fetch()) {
    echo $zeile['name'];
}

do {
    // läuft mindestens einmal
} while ($bedingung);

foreach ist die wichtigste Schleife in PHP, da man damit Arrays ohne Index durchläuft: 

foreach ($fruits as $fruit) {
    echo $fruit;
}

foreach ($person as $key => $value) {
    echo "$key: $value";
}

foreach ($items as &$item) {
    $item = strtoupper($item); // & verändert das Original-Array
}
unset($item); // Referenz nach der Schleife auflösen

break verlässt die Schleife, continue springt zum nächsten Durchlauf. Mit break 2 / continue 2 auch über zwei Ebenen.

Arrays

Arrays in PHP werden mit dem array()-Konstrukt oder der Kurzsyntax [] erstellt. Ein PHP-Array ist technisch immer eine geordnete Map, deshalb gibt es keinen Unterschied zwischen "Liste" und "Dictionary". 

$fruits = array("Apfel", "Banane", "Orange");
$fruits = ["Apfel", "Banane", "Orange"]; // bevorzugt

Der Zugriff auf Array-Elemente erfolgt über den Index:

echo $fruits[0];   // "Apfel"
$fruits[] = "Kiwi"; // anhängen

Ebenso gibt es assoziative Arrays, bei denen Schlüssel benannt werden. Der Zugriff erfolgt dann über den Schlüssel. 

$person = ["name" => "John", "age" => 30];
echo $person["name"]; // "John"

Mehrdimensionale Arrays sind einfach Arrays in Arrays:

$users = [
    ["name" => "John", "age" => 30],
    ["name" => "Jane", "age" => 25],
];
echo $users[1]["name"]; // "Jane"

Wichtige Array-Funktionen

  • count() – Anzahl der Elemente in einem Array oder eines Objekts
  • in_array($wert, $array) – enthält das Array den Wert? (mit true als 3. Parameter strikt vergleichen)
  • array_key_exists($key, $array) – existiert der Schlüssel?
  • array_keys() / array_values()
  • array_map(fn($x) => $x * 2, $array) – jeden Wert transformieren
  • array_filter($array, fn($x) => $x > 10) – filtern
  • array_reduce() – auf einen Wert zusammenfassen (z.B. Summe)
  • array_column($users, 'name') – eine Spalte aus Datensätzen ziehen
  • array_merge() – zusammenfügen, array_unique(), array_slice(), array_search()
  • sort() / rsort() / asort() (nach Wert, Schlüssel bleiben) / ksort() (nach Schlüssel) / usort() (eigene Funktion)
  • array_sum(), min(), max()
  • unset($array[2]) – Element löschen (Indizes bleiben lückenhaft, mit array_values() neu durchnummerieren)

Destrukturierung und Spread:

[$a, $b] = [1, 2];
['name' => $name] = $person;
$alle = [...$array1, ...$array2];

Funktionen

Funktionen in PHP werden mit dem function-Schlüsselwort definiert. Sie können Parameter entgegennehmen und Werte zurückgeben. 

function greet($name) {
    return "Hallo " . $name;
}
echo greet("John");

Mit Typdeklarationen wird der Code deutlich sicherer und selbsterklärend. ?string bedeutet "string oder null", void heißt "gibt nichts zurück". 

function greet(string $name, string $gruss = "Hallo"): string {
    return "$gruss $name";
}

greet("John");                  // Standardwert wird genutzt
greet(name: "John", gruss: "Hi"); // Named Arguments, ab PHP 8

Variable Anzahl von Parametern mit ... (Variadic):

function summe(int ...$zahlen): int {
    return array_sum($zahlen);
}
echo summe(1, 2, 3); // 6

Closures und Arrow Functions

Anonyme Funktionen lassen sich in Variablen speichern und als Callback übergeben. Eine Closure muss äußere Variablen mit use importieren, eine Arrow Function (fn) übernimmt sie automatisch. 

$faktor = 3;

$mal = function ($x) use ($faktor) {
    return $x * $faktor;
};

$mal = fn($x) => $x * $faktor; // kurz, ab PHP 7.4

$ergebnis = array_map($mal, [1, 2, 3]);

Referenzen

Normalerweise werden Werte kopiert übergeben. Mit & vor dem Parameter wird das Original verändert. Objekte werden dagegen immer als Referenz auf dieselbe Instanz behandelt. 

function addiere(array &$liste, $wert) {
    $liste[] = $wert;
}

Includes / Requires

include und require werden verwendet, um externe PHP-Dateien einzubinden. 

include 'header.php';
require 'config.php';
require_once __DIR__ . '/config.php'; // empfohlen

Der Unterschied besteht darin, dass require einen fatalen Fehler auslöst, wenn die Datei nicht gefunden wird, während include nur eine Warnung ausgibt und weiterläuft.

Die _once-Varianten binden eine Datei nur einmal ein und verhindern damit "Cannot redeclare function"-Fehler. Für Konfiguration und Klassen immer require_once verwenden, für Template-Teile include.

Pfade immer absolut über __DIR__ aufbauen – relative Pfade beziehen sich auf das aufrufende Skript und brechen, sobald die Datei von woanders eingebunden wird.

Superglobale Variablen (Superglobals)

Superglobale Variablen sind vordefinierte Arrays, die PHP bei jedem Request automatisch füllt. Sie heißen "superglobal", weil sie in jedem Gültigkeitsbereich verfügbar sind – also auch innerhalb von Funktionen und Methoden, ohne dass man sie mit global importieren oder als Parameter übergeben muss. Das ist der einzige Unterschied zu normalen globalen Variablen. 

function zeigeMethode() {
    echo $_SERVER['REQUEST_METHOD']; // funktioniert ohne global
}

Es gibt genau neun davon:

  • $GLOBALS – alle globalen Variablen
  • $_SERVER – Server- und Request-Informationen
  • $_GET – Daten aus der URL
  • $_POST – Daten aus einem POST-Request
  • $_FILES – hochgeladene Dateien
  • $_COOKIE – Cookies des Browsers
  • $_SESSION – serverseitiger Speicher pro Besucher
  • $_REQUEST – Mischung aus GET, POST und COOKIE
  • $_ENV – Umgebungsvariablen

Grundregel: $_GET, $_POST, $_COOKIE, $_FILES, $_REQUEST und große Teile von $_SERVER kommen vom Benutzer und sind grundsätzlich als nicht vertrauenswürdig zu behandeln – immer auf Existenz prüfen, validieren und beim Ausgeben escapen. Nur $_SESSION und $_ENV liegen auf dem Server und sind damit vertrauenswürdig.

$_GET

Enthält die Parameter aus dem Query-String der URL, also alles nach dem Fragezeichen, sowie die Felder eines Formulars mit method="get". Die Werte stehen sichtbar in der Adresszeile, lassen sich als Lesezeichen speichern und landen im Browserverlauf und in Serverlogs. Deshalb nur für Filter, Suche, Sortierung und Seitenzahlen verwenden – nie für Passwörter. 

// Aufruf: /produkte.php?kategorie=oefen&seite=2

$kategorie = $_GET['kategorie'] ?? 'alle';
$seite     = (int) ($_GET['seite'] ?? 1);

// Sicher weiterverwenden
$seite = max(1, $seite);
echo htmlspecialchars($kategorie, ENT_QUOTES, 'UTF-8');

Die Werte sind immer Strings (oder Arrays), auch wenn in der URL eine Zahl steht – daher die Umwandlung mit (int) oder die Prüfung mit filter_var(). Mehrere Werte unter einem Namen gehen mit eckigen Klammern: ?tags[]=a&tags[]=b liefert in $_GET['tags'] ein Array.

Beim Zusammenbauen von Links müssen Werte kodiert werden: urlencode($wert) bzw. http_build_query(['kategorie' => $k, 'seite' => 2]).

$_POST

Enthält die Felder eines Formulars mit method="post". Die Daten stehen im Body des Requests, sind also nicht in der URL sichtbar und werden nicht geloggt oder als Lesezeichen gespeichert. Für alles, was Daten verändert (anlegen, ändern, löschen, Login, Mailversand) oder vertraulich ist. 

<form method="post" action="speichern.php">
    <input type="text" name="name">
    <input type="email" name="email">
    <button type="submit">Senden</button>
</form>
// Der Schlüssel ist das name-Attribut des Feldes
$name  = trim($_POST['name'] ?? '');
$email = trim($_POST['email'] ?? '');

Wichtige Punkte, die immer wieder für Fehler sorgen:

  • Felder ohne name-Attribut werden nicht mitgesendet und fehlen in $_POST.
  • Nicht angekreuzte Checkboxen sind überhaupt nicht in $_POST enthalten – daher mit isset($_POST['agb']) prüfen, nicht auf den Wert.
  • Ein deaktiviertes Feld (disabled) wird nicht gesendet, ein readonly-Feld schon.
  • Für Datei-Uploads muss das Formular enctype="multipart/form-data" haben – sonst bleibt $_FILES leer.
  • Ist der Request größer als post_max_size (php.ini), sind $_POST und $_FILES komplett leer.
  • $_POST wird nur bei application/x-www-form-urlencoded und multipart/form-data gefüllt. Bei einem JSON-Body (typisch bei AJAX/fetch) ist $_POST leer, dann muss der Rohinhalt gelesen werden: 
$daten = json_decode(file_get_contents('php://input'), true);

Ob überhaupt ein POST vorliegt, prüft man über $_SERVER, nicht über leere Felder: 

if ($_SERVER['REQUEST_METHOD'] === 'POST') { /* verarbeiten */ }

$_REQUEST

Enthält GET-, POST- und Cookie-Werte in einem Array. Welche Quellen in welcher Reihenfolge einfließen, hängt von der php.ini-Einstellung variables_order ab – bei Namensgleichheit überschreibt die spätere Quelle die frühere.

Sollte man nicht verwenden. Die Herkunft eines Wertes ist nicht erkennbar, wodurch sich ein POST-Wert über einen URL-Parameter oder ein gesetztes Cookie unterschieben lässt. Zusätzlich lässt sich damit die Request-Methode nicht mehr kontrollieren – ein Formular, das eigentlich nur per POST absendbar sein soll, funktioniert plötzlich auch über einen Link. Immer gezielt $_GET oder $_POST abfragen.

$_COOKIE

Enthält alle Cookies, die der Browser mit dem Request mitgeschickt hat. Cookies werden beim Benutzer gespeichert und sind dort beliebig manipulierbar – also nie für Berechtigungen oder Preise verwenden, sondern nur für unkritische Dinge wie Theme, Sprache oder Cookie-Banner-Zustand. 

// Setzen (muss vor jeder Ausgabe passieren)
setcookie('theme', 'dark', [
    'expires'  => time() + 86400 * 30,
    'path'     => '/',
    'secure'   => true,   // nur über HTTPS
    'httponly' => true,   // kein Zugriff per JavaScript
    'samesite' => 'Lax',
]);

// Lesen
$theme = $_COOKIE['theme'] ?? 'light';

// Löschen: Zeitpunkt in die Vergangenheit setzen
setcookie('theme', '', time() - 3600, '/');

Wichtig: Ein gerade gesetztes Cookie steht erst beim nächsten Request in $_COOKIE – unmittelbar nach setcookie() ist es dort noch nicht enthalten. Pro Cookie sind rund 4 KB möglich, und sie werden bei jedem Request mitgesendet.

$_SESSION

Der serverseitige Speicher pro Besucher. Der Browser erhält nur eine Session-ID als Cookie (PHPSESSID), die eigentlichen Daten liegen auf dem Server und sind damit nicht manipulierbar. Deshalb gehören Login-Status und Berechtigungen in die Session, nicht in ein Cookie.

Vor jedem Zugriff muss session_start() aufgerufen werden – und zwar vor jeder Ausgabe, da dabei ein Cookie-Header gesendet wird. 

session_start();

$_SESSION['user'] = "John";
$_SESSION['user_id'] = 42;

if (isset($_SESSION['user_id'])) {
    // eingeloggt
}

unset($_SESSION['user']);   // einen Wert entfernen
session_unset();            // alle Werte leeren
session_destroy();          // Session serverseitig löschen

$_SESSION ist ein assoziatives Array mit Schlüssel-Wert-Paaren und kann beliebig verschachtelt werden, z.B. $_SESSION = ['configurator' => [1 => 'Holzofen', 2 => 'Front', 3 => 'Zubehör']]; 

// verschachtelt lesen und schreiben
$_SESSION['configurator'][2] = 'Front schwarz';
$schritt = $_SESSION['configurator'][1] ?? null;

Lebensdauer und Sicherheit werden über die php.ini gesteuert (session.gc_maxlifetime, session.cookie_httponly, session.cookie_secure, session.use_strict_mode). Nach einem Login immer session_regenerate_id(true) aufrufen, um Session Fixation zu verhindern.

$_FILES

Enthält die hochgeladenen Dateien eines multipart-Formulars. Pro Feld entsteht ein Array mit fünf Schlüsseln. 

$_FILES['datei']['name']      // Originalname beim Benutzer
$_FILES['datei']['type']      // vom Browser gemeldeter MIME-Typ (nicht vertrauen!)
$_FILES['datei']['tmp_name']  // temporärer Pfad auf dem Server
$_FILES['datei']['error']     // Fehlercode, 0 = UPLOAD_ERR_OK
$_FILES['datei']['size']      // Größe in Bytes
$_FILES['datei']['full_path'] // relativer Pfad bei Ordner-Uploads (ab PHP 8.1)
if (($_FILES['datei']['error'] ?? UPLOAD_ERR_NO_FILE) === UPLOAD_ERR_OK) {

    // MIME-Typ serverseitig ermitteln, nicht ['type'] glauben
    $mime = mime_content_type($_FILES['datei']['tmp_name']);
    $erlaubt = ['image/jpeg' => 'jpg', 'image/png' => 'png'];

    if (isset($erlaubt[$mime])) {
        // Dateinamen selbst erzeugen, nie den Originalnamen übernehmen
        $ziel = __DIR__ . '/uploads/' . bin2hex(random_bytes(16))
              . '.' . $erlaubt[$mime];

        move_uploaded_file($_FILES['datei']['tmp_name'], $ziel);
    }
}

Die temporäre Datei wird am Ende des Requests automatisch gelöscht – sie muss mit move_uploaded_file() verschoben werden, nicht mit copy() oder rename(). Die Größenbegrenzung kommt aus der php.ini (upload_max_filesize, post_max_size, max_file_uploads).

$_SERVER

Informationen über Server, Request und Umgebung. Der Inhalt hängt vom Webserver ab, die wichtigsten Schlüssel sind aber überall vorhanden.

  • REQUEST_METHOD – GET, POST, PUT, DELETE
  • REQUEST_URI – angefragter Pfad inkl. Query-String
  • QUERY_STRING – nur der Teil nach dem Fragezeichen
  • SCRIPT_NAME / PHP_SELF – Pfad des laufenden Skripts
  • DOCUMENT_ROOT – Wurzelverzeichnis des Webservers
  • SCRIPT_FILENAME – absoluter Pfad des Skripts
  • HTTP_HOST / SERVER_NAME – Domain
  • HTTPS – gesetzt, wenn die Verbindung verschlüsselt ist
  • REMOTE_ADDR – IP-Adresse des Besuchers
  • HTTP_USER_AGENT – Browser des Benutzers
  • HTTP_REFERER – vorherige Seite, vom Browser gesendet und damit fälschbar
  • HTTP_ACCEPT_LANGUAGE – Sprachwunsch des Browsers
  • CONTENT_TYPE / CONTENT_LENGTH – Angaben zum Request-Body
  • SERVER_SOFTWARE, SERVER_PORT, SERVER_PROTOCOL
  • REQUEST_TIME / REQUEST_TIME_FLOAT – Startzeit des Requests
  • argv / argc – Kommandozeilenargumente in der CLI
// HTTPS erkennen
$istHttps = !empty($_SERVER['HTTPS']) && $_SERVER['HTTPS'] !== 'off';

// Vollständige aktuelle URL
$url = ($istHttps ? 'https://' : 'http://')
     . $_SERVER['HTTP_HOST'] . $_SERVER['REQUEST_URI'];

// Zwischen lokal und live unterscheiden
$lokal = in_array($_SERVER['HTTP_HOST'] ?? '', ['localhost:8000', '127.0.0.1'], true);

Achtung: alle Schlüssel, die mit HTTP_ beginnen, stammen aus Headern des Browsers und sind frei fälschbar – das gilt auch für HTTP_HOST, HTTP_REFERER und HTTP_X_FORWARDED_FOR. Niemals für Sicherheitsentscheidungen nutzen. PHP_SELF gehört vor der Ausgabe durch htmlspecialchars(), da sich darüber sonst XSS einschleusen lässt. Hinter einem Proxy oder Loadbalancer ist REMOTE_ADDR die IP des Proxys, nicht die des Besuchers.

$_ENV und getenv()

Enthält die Umgebungsvariablen des Prozesses. Der typische Einsatz sind Zugangsdaten (Datenbank, SMTP, API-Keys), die nicht im Code und nicht im Git stehen sollen. 

$dbPass = $_ENV['DB_PASSWORD'] ?? getenv('DB_PASSWORD');

putenv('APP_ENV=production'); // zur Laufzeit setzen

$_ENV ist oft leer, weil die php.ini-Einstellung variables_order standardmäßig "GPCS" lautet und das E für Environment fehlt. getenv() funktioniert unabhängig davon und ist daher der zuverlässigere Weg. In der Praxis liest man .env-Dateien meist mit der Composer-Bibliothek vlucas/phpdotenv ein. Die .env-Datei gehört in die .gitignore und außerhalb des Webroots bzw. muss vom Webserver blockiert werden.

$GLOBALS

Ein Array aller globaler Variablen, zugänglich über den Variablennamen als Schlüssel: $GLOBALS['x']. Damit ließe sich innerhalb einer Funktion auf eine äußere Variable zugreifen – gilt aber wie global als schlechter Stil, da Abhängigkeiten unsichtbar werden. Seit PHP 8.1 ist das Array nur noch eingeschränkt beschreibbar. Parameter und Rückgabewerte sind der saubere Weg.

Formulare verarbeiten

<?php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $name  = trim($_POST['name'] ?? '');
    $email = trim($_POST['email'] ?? '');
    $errors = [];

    if ($name === '') {
        $errors[] = 'Name fehlt';
    }
    if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
        $errors[] = 'E-Mail ungültig';
    }

    if (!$errors) {
        // speichern / Mail senden
        header('Location: /danke.php');
        exit; // nach header immer exit!
    }
}

filter_var() validiert mit FILTER_VALIDATE_EMAIL, FILTER_VALIDATE_INT, FILTER_VALIDATE_URL. Nach einem header('Location: ...') muss immer exit folgen, sonst läuft das Skript weiter.

Nach erfolgreichem POST auf eine andere Seite weiterleiten (Post-Redirect-Get). Sonst führt ein Reload im Browser zum doppelten Absenden.

Sessions und Cookies

Eine Session speichert Daten auf dem Server, der Browser erhält nur eine Session-ID als Cookie. Ein Cookie speichert die Daten dagegen beim Benutzer und ist dort manipulierbar – also nie für Berechtigungen nutzen. 

session_start(); // muss vor jeder Ausgabe stehen

$_SESSION['user_id'] = 42;

// Login-Prüfung
if (!isset($_SESSION['user_id'])) {
    header('Location: /login.php');
    exit;
}

// nach dem Login die ID wechseln (gegen Session Fixation)
session_regenerate_id(true);

// Logout
session_unset();
session_destroy();
setcookie('theme', 'dark', [
    'expires'  => time() + 86400 * 30,
    'path'     => '/',
    'secure'   => true,   // nur über HTTPS
    'httponly' => true,   // kein Zugriff per JavaScript
    'samesite' => 'Lax',  // gegen CSRF
]);

Ein gesetztes Cookie steht erst beim nächsten Request in $_COOKIE.

Objektorientierung (OOP)

Ab einer bestimmten Projektgröße führt kein Weg an Klassen vorbei – auch Redaxo, Symfony und Laravel sind komplett objektorientiert aufgebaut. 

class User
{
    public const ROLE_ADMIN = 'admin';

    private array $roles = [];

    public function __construct(
        private string $name,
        private string $email,
    ) {}

    public function getName(): string
    {
        return $this->name;
    }

    public function addRole(string $role): static
    {
        $this->roles[] = $role;
        return $this; // erlaubt Method Chaining
    }
}

$user = new User('John', 'john@example.com');
echo $user->getName();

Die Schreibweise im Konstruktor nennt sich Constructor Property Promotion (ab PHP 8) und erzeugt die Eigenschaften automatisch. Auf Eigenschaften und Methoden der eigenen Instanz greift man mit $this-> zu, auf statische mit self:: oder Klasse::.

Sichtbarkeit

  • public – von überall zugänglich
  • protected – nur in der Klasse und ihren Kindklassen
  • private – nur in der Klasse selbst

Grundregel: Eigenschaften private oder protected, Zugriff über Methoden (Getter/Setter). readonly (ab PHP 8.1) erlaubt das Setzen nur einmal im Konstruktor.

Vererbung, Interfaces, abstrakte Klassen, Traits

  • extends – erbt Eigenschaften und Methoden einer Elternklasse. Mit parent::__construct() wird der Eltern-Konstruktor aufgerufen.
  • interface – schreibt nur Methodensignaturen vor, ohne Code. Eine Klasse kann mehrere Interfaces implements-ieren.
  • abstract class – kann nicht direkt instanziiert werden und mischt fertige mit vorgeschriebenen Methoden.
  • trait – wiederverwendbare Methodenblöcke, die per use in Klassen eingebunden werden. Lösung für das Problem, dass PHP keine Mehrfachvererbung kennt.
  • static – Eigenschaft oder Methode gehört zur Klasse, nicht zur Instanz: User::count().
  • final – verhindert Überschreiben bzw. Erben.

Enums

Ab PHP 8.1 ersetzen Enums lose Konstanten und machen ungültige Werte unmöglich. 

enum Status: string
{
    case Draft     = 'draft';
    case Published = 'published';

    public function label(): string
    {
        return match($this) {
            Status::Draft     => 'Entwurf',
            Status::Published => 'Veröffentlicht',
        };
    }
}

$status = Status::from('draft');
echo $status->label();

Magic Methods

Methoden mit doppeltem Unterstrich, die PHP automatisch aufruft: __construct, __destruct, __toString (Objekt als String ausgeben), __get / __set (Zugriff auf nicht existierende Eigenschaften), __call, __invoke (Objekt wie Funktion aufrufen).

Namespaces, Composer und Autoloading

Namespaces verhindern Namenskonflikte zwischen Klassen gleichen Namens aus verschiedenen Bibliotheken. 

// src/Mail/Sender.php
namespace App\Mail;

class Sender {}

// Verwendung
use App\Mail\Sender;
$sender = new Sender();

Composer ist der Paketmanager von PHP (das Pendant zu npm / yarn). composer.json beschreibt die Abhängigkeiten, composer.lock fixiert die exakten Versionen, der Ordner vendor/ enthält den Code und wird nicht ins Git eingecheckt. 

composer require phpmailer/phpmailer
composer install     // installiert gemäß composer.lock
composer update      // aktualisiert auf neue Versionen
composer dump-autoload

Eine einzige Zeile ersetzt dann alle require-Aufrufe – Klassen werden anhand ihres Namespaces automatisch geladen (PSR-4): 

require_once __DIR__ . '/vendor/autoload.php';

PSR sind die PHP-Standards der PHP-FIG: PSR-4 (Autoloading), PSR-12 (Code-Style), PSR-3 (Logging), PSR-7 (HTTP). Daran halten sich praktisch alle modernen Bibliotheken.

Fehlerbehandlung

PHP unterscheidet Errors (Fehler in der Sprache, z.B. TypeError, DivisionByZeroError) und Exceptions (Ausnahmen der Anwendung). Beide lassen sich mit Throwable abfangen. 

try {
    $pdo = new PDO($dsn, $user, $pass);
} catch (PDOException $e) {
    error_log($e->getMessage());   // ins Log, nicht an den Benutzer
    http_response_code(500);
    echo 'Es ist ein Fehler aufgetreten.';
} finally {
    // läuft immer, z.B. zum Aufräumen
}

// eigene Ausnahme werfen
if ($menge < 0) {
    throw new InvalidArgumentException('Menge darf nicht negativ sein');
}

Fehlermeldungen gehören in der Produktion ins Log, nie auf den Bildschirm – sie verraten Pfade, Datenbanknamen und Zugangsdaten. Gesteuert wird das über display_errors und log_errors in der php.ini.

Mit set_exception_handler() und register_shutdown_function() lässt sich eine zentrale Fehlerseite umsetzen.

Datenbankzugriff mit PDO

PDO (PHP Data Objects) ist die empfohlene Datenbank-Schnittstelle, da sie mit verschiedenen Datenbanken funktioniert und Prepared Statements sauber unterstützt. mysqli geht nur für MySQL. 

$pdo = new PDO(
    'mysql:host=localhost;dbname=shop;charset=utf8mb4',
    $user,
    $pass,
    [
        PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
        PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
        PDO::ATTR_EMULATE_PREPARES   => false,
    ]
);

// Lesen mit Platzhalter
$stmt = $pdo->prepare('SELECT * FROM users WHERE email = :email');
$stmt->execute(['email' => $email]);
$user = $stmt->fetch();          // ein Datensatz
$alle = $stmt->fetchAll();       // alle Datensätze

// Schreiben
$stmt = $pdo->prepare('INSERT INTO users (name, email) VALUES (?, ?)');
$stmt->execute([$name, $email]);
$id = $pdo->lastInsertId();

Die drei Optionen oben sind Pflicht: ERRMODE_EXCEPTION wirft bei Fehlern eine Exception statt stillschweigend false zurückzugeben, FETCH_ASSOC liefert lesbare assoziative Arrays, und EMULATE_PREPARES => false sorgt für echte, von der Datenbank geprüfte Prepared Statements.

Transaktionen für mehrere zusammenhängende Schreibvorgänge: $pdo->beginTransaction(), $pdo->commit(), im catch-Block $pdo->rollBack().

Sicherheit

Die wichtigsten Punkte, die in jedem PHP-Projekt sitzen müssen:

  • SQL-Injection – niemals Benutzereingaben in einen SQL-String kleben. Immer Prepared Statements mit Platzhaltern. Tabellen- und Spaltennamen lassen sich nicht binden, die müssen gegen eine Whitelist geprüft werden.
  • XSS (Cross-Site-Scripting) – jede Benutzereingabe beim Ausgeben escapen: htmlspecialchars($text, ENT_QUOTES, 'UTF-8'). Nicht beim Speichern escapen, sondern beim Ausgeben.
  • CSRF – bei jedem Formular ein Token in der Session ablegen, als hidden-Feld mitsenden und beim POST mit hash_equals() vergleichen.
  • Passwörter – nur mit password_hash($pw, PASSWORD_DEFAULT) speichern und mit password_verify($pw, $hash) prüfen. Niemals md5 oder sha1.
  • Datei-Uploads – Zieldateinamen selbst erzeugen, MIME-Typ serverseitig prüfen (finfo, nicht $_FILES['type']), Uploads außerhalb des Webroots oder ohne PHP-Ausführung ablegen.
  • Path Traversal – nie include $_GET['page'] verwenden. Immer gegen eine Whitelist erlaubter Werte prüfen.
  • Zugangsdaten – nicht im Code und nicht im Git, sondern in einer .env-Datei oder Umgebungsvariablen außerhalb des Webroots.
  • Fehleranzeige – display_errors in der Produktion aus (siehe php.ini). 
// Token erzeugen
$_SESSION['csrf'] = bin2hex(random_bytes(32));

// im Formular
<input type="hidden" name="csrf" value="<?= $_SESSION['csrf'] ?>">

// beim Absenden prüfen
if (!hash_equals($_SESSION['csrf'], $_POST['csrf'] ?? '')) {
    http_response_code(403);
    exit('Ungültige Anfrage');
}

JSON, Dateien und Datum

// JSON
$json = json_encode($daten, JSON_UNESCAPED_UNICODE | JSON_THROW_ON_ERROR);
$array = json_decode($json, true); // true = assoziatives Array statt Objekt

// JSON an den Browser ausgeben (z.B. für AJAX)
header('Content-Type: application/json');
echo json_encode(['status' => 'ok']);

// Dateien
$inhalt = file_get_contents(__DIR__ . '/data.txt');
file_put_contents($pfad, $inhalt, FILE_APPEND);
$zeilen = file($pfad, FILE_IGNORE_NEW_LINES);
if (file_exists($pfad)) { /* ... */ }

// Datum
$jetzt = new DateTimeImmutable('now');
echo $jetzt->format('d.m.Y H:i');
echo $jetzt->modify('+7 days')->format('Y-m-d');
$diff = $jetzt->diff(new DateTimeImmutable('2026-12-24'));
echo $diff->days;

DateTimeImmutable ist DateTime vorzuziehen, weil Änderungen ein neues Objekt zurückgeben und nicht das bestehende verändern. Damit das Datum stimmt, muss date.timezone in der php.ini gesetzt sein.

php.ini

Die php.ini ist die zentrale Konfigurationsdatei von PHP. Sie wird beim Start des PHP-Prozesses eingelesen und bestimmt, wie PHP sich verhält: welche Erweiterungen geladen werden, wie viel Speicher und Laufzeit ein Skript bekommt, wie groß Uploads sein dürfen, ob Fehler angezeigt oder geloggt werden und wie Sessions arbeiten.

Welche php.ini gilt überhaupt?

Der häufigste Stolperstein: es gibt meist mehrere php.ini-Dateien – eine für die CLI und eine für den Webserver (PHP-FPM oder mod_php). Eine Änderung auf der Kommandozeile wirkt daher nicht automatisch auf der Website. 

php --ini              # zeigt den Pfad der geladenen Datei (CLI)
php -i | grep "Loaded Configuration File"

Für den Webserver ist phpinfo() der zuverlässige Weg. Eine Datei mit <?php phpinfo(); anlegen, aufrufen, die Zeile "Loaded Configuration File" ablesen – und die Datei danach wieder löschen, da sie sonst die komplette Serverkonfiguration öffentlich preisgibt.

Zusätzlich gibt es ein Scan-Verzeichnis (meist /etc/php/8.3/fpm/conf.d/), dessen .ini-Dateien in alphabetischer Reihenfolge nach der php.ini geladen werden. Dort liegen typischerweise die Erweiterungen. Wer in der php.ini etwas setzt, das später in der conf.d überschrieben wird, sucht lange nach dem Grund.

Nach jeder Änderung muss PHP neu gestartet werden, bei der CLI genügt der nächste Aufruf: 

sudo systemctl restart php8.3-fpm
sudo systemctl restart apache2     # bei mod_php

Syntax

Pro Zeile eine Direktive, Kommentare beginnen mit einem Semikolon. Werte lassen sich mit Einheiten (K, M, G) und Konstanten (On/Off, Zahlen, Konstanten wie E_ALL) schreiben. Ein führendes Semikolon ist der klassische Fehler: die Zeile ist dann auskommentiert und wirkungslos. 

; so sieht ein Kommentar aus
memory_limit = 256M
display_errors = Off
error_reporting = E_ALL & ~E_DEPRECATED
date.timezone = "Europe/Berlin"
extension = intl

php.ini-development und php.ini-production

PHP liefert zwei Vorlagen mit. php.ini-development zeigt alle Fehler direkt im Browser, php.ini-production versteckt sie und schreibt sie ins Log. Auf einem Live-Server ist immer die Production-Variante die Basis.

Fehlerbehandlung

  • display_errors – Fehler im Browser anzeigen. Lokal On, produktiv Off. Angezeigte Fehler verraten Pfade, Datenbanknamen und teils Zugangsdaten.
  • display_startup_errors – Fehler beim Start von PHP anzeigen (z.B. fehlende Extension). Produktiv Off.
  • error_reporting – welche Fehlerarten gemeldet werden. Entwicklung: E_ALL. Produktiv typischerweise E_ALL & ~E_DEPRECATED & ~E_STRICT.
  • log_errors – Fehler ins Log schreiben. Immer On.
  • error_log – Pfad der Logdatei, z.B. /var/log/php/error.log. Ohne Angabe landen die Meldungen im Log des Webservers.

Laufzeit und Speicher

  • memory_limit – maximaler Speicher pro Skript (z.B. 128M, 256M). Bei "Allowed memory size exhausted" ist das die Ursache. -1 bedeutet unbegrenzt und ist nur für die CLI sinnvoll.
  • max_execution_time – maximale Laufzeit in Sekunden (Standard 30). Verursacht "Maximum execution time exceeded". Gilt nicht für die CLI (dort 0). Achtung: bei PHP-FPM begrenzt zusätzlich request_terminate_timeout, bei nginx fastcgi_read_timeout.
  • max_input_time – wie lange PHP Eingabedaten einlesen darf.
  • max_input_vars – maximale Anzahl an Eingabevariablen (Standard 1000). Große Formulare, etwa in Redaxo- oder WordPress-Backends, werden sonst stillschweigend abgeschnitten.

Datei-Uploads

  • file_uploads – Uploads grundsätzlich erlauben (On)
  • upload_max_filesize – maximale Größe einer einzelnen Datei
  • post_max_size – maximale Größe des gesamten POST-Requests
  • max_file_uploads – Anzahl Dateien pro Request (Standard 20)
  • upload_tmp_dir – temporäres Verzeichnis für Uploads

Diese drei Werte hängen voneinander ab und müssen in der richtigen Reihenfolge stehen – sonst greift die kleinste Grenze und der Upload scheitert ohne klare Meldung: 

upload_max_filesize = 32M
post_max_size       = 40M   ; größer als upload_max_filesize
memory_limit        = 128M  ; größer als post_max_size

Wird post_max_size überschritten, sind $_POST und $_FILES komplett leer – ein Verhalten, das gern für Verwirrung sorgt. Bei nginx muss zusätzlich client_max_body_size passen.

Sessions

  • session.save_path – Speicherort der Session-Dateien
  • session.gc_maxlifetime – nach wie vielen Sekunden Sessions als Müll gelten (Standard 1440 = 24 Minuten). Zu niedrig bedeutet: Benutzer werden mitten in der Arbeit ausgeloggt.
  • session.cookie_lifetime – Lebensdauer des Session-Cookies im Browser, 0 heißt "bis der Browser geschlossen wird"
  • session.cookie_httponly = 1 – kein Zugriff per JavaScript, schützt die Session-ID bei XSS
  • session.cookie_secure = 1 – Cookie nur über HTTPS senden
  • session.cookie_samesite = Lax – schützt gegen CSRF
  • session.use_strict_mode = 1 – PHP akzeptiert keine selbst erfundenen Session-IDs, verhindert Session Fixation
  • session.use_only_cookies = 1 – keine Session-ID in der URL

Zeichensatz und Zeitzone

  • date.timezone = "Europe/Berlin" – muss gesetzt sein, sonst arbeiten date() und DateTime mit UTC und alle Zeitstempel sind verschoben.
  • default_charset = "UTF-8" – Zeichensatz für Header und htmlspecialchars().
  • mbstring.* – Einstellungen der Multibyte-Erweiterung für Umlaute und Sonderzeichen.

Mail

  • sendmail_path – Programm, an das die PHP-Funktion mail() die Nachricht übergibt (unter Linux meist /usr/sbin/sendmail -t -i). Genau dieser Weg wird bei Mailertyp "mail" genutzt.
  • SMTP und smtp_port – nur unter Windows relevant.
  • mail.add_x_header – fügt einen X-PHP-Originating-Script Header hinzu, hilfreich beim Aufspüren von Spam-Skripten.
  • mail.log – protokolliert alle mail()-Aufrufe.

Für zuverlässigen Mailversand ist SMTP mit Authentifizierung über PHPMailer trotzdem die bessere Wahl als mail() – siehe die Seite zum PHP Mailer.

Sicherheitsrelevante Direktiven

  • expose_php = Off – entfernt den X-Powered-By Header, der die PHP-Version verrät.
  • allow_url_fopen – erlaubt file_get_contents() mit URLs. Wenn möglich Off und stattdessen cURL nutzen.
  • allow_url_include = Off – darf nie On sein, sonst lässt sich Fremdcode einbinden und ausführen.
  • disable_functions – sperrt gefährliche Funktionen wie exec, shell_exec, system, passthru, popen auf Shared Hosting.
  • open_basedir – beschränkt Dateizugriffe auf bestimmte Verzeichnisse, isoliert damit mehrere Projekte auf einem Server voneinander.
  • short_open_tag = Off – verbietet <? als Kurzform. <?= funktioniert davon unabhängig immer.
  • cgi.fix_pathinfo = 0 – bei nginx und PHP-FPM wichtig, verhindert das Ausführen untergeschobener Dateien.

OPcache (Performance)

OPcache hält den kompilierten PHP-Bytecode im Speicher, sodass Dateien nicht bei jedem Request neu geparst werden. Das ist der größte einzelne Performance-Faktor und sollte produktiv immer aktiv sein. 

opcache.enable = 1
opcache.memory_consumption = 256
opcache.max_accelerated_files = 20000
opcache.validate_timestamps = 1   ; produktiv 0, dann nach Deploy neu starten
opcache.revalidate_freq = 2
opcache.jit = tracing             ; JIT, ab PHP 8

Steht validate_timestamps auf 0, bemerkt PHP Dateiänderungen nicht – praktisch für maximale Geschwindigkeit, erfordert aber nach jedem Deploy einen Neustart von PHP-FPM. Lokal gehört der Wert auf 1, sonst wirken Codeänderungen scheinbar nicht.

Erweiterungen

Erweiterungen werden mit extension = geladen, in Ubuntu/Debian üblicherweise über eigene Dateien im conf.d-Verzeichnis. 

extension = pdo_mysql
extension = mbstring
extension = intl
extension = gd
extension = curl
extension = zip

Prüfen lassen sich geladene Erweiterungen mit php -m oder extension_loaded('gd'). Fehlt eine Erweiterung, ist die Fehlermeldung oft nur "Class 'PDO' not found" oder "Call to undefined function curl_init()".

Werte überschreiben – ohne Zugriff auf die php.ini

Auf Shared Hosting gibt es oft keinen Zugriff auf die php.ini. Es gibt mehrere Ebenen, jede mit eigenen Grenzen:

  • ini_set('memory_limit', '256M'); – zur Laufzeit im Skript. Funktioniert nur bei Direktiven, die als PHP_INI_ALL markiert sind. memory_limit, max_execution_time und display_errors gehen, upload_max_filesize und post_max_size nicht, weil sie beim Einlesen des Requests schon ausgewertet sind.
  • .user.ini – Datei im Projektverzeichnis, wirkt bei PHP-FPM/CGI. Sie wird gecacht (user_ini.cache_ttl, Standard 300 Sekunden), Änderungen greifen also verzögert.
  • .htaccess mit php_value / php_flag – funktioniert nur mit mod_php. Unter PHP-FPM führt es zu einem 500er-Fehler.
  • FPM-Pool-Konfiguration (www.conf) mit php_value bzw. php_admin_value. Die admin-Varianten können im Skript nicht mehr überschrieben werden. 
; .user.ini im Projektordner
upload_max_filesize = 64M
post_max_size = 72M
max_execution_time = 120

Den aktuell geltenden Wert liefert ini_get('upload_max_filesize') – nützlich, um zu prüfen, ob eine Änderung wirklich angekommen ist.

Wichtige eingebaute Funktionen (Überblick)

count()

Gibt die Anzahl der Elemente in einem Array oder eines Objekts zurück.

Debugging

var_dump() (Typ und Wert), print_r() (lesbar für Arrays), error_log() (ins Serverlog), debug_print_backtrace(), die() / exit(). Für ernsthaftes Debugging ist Xdebug mit Breakpoints der richtige Weg.

Sonstiges

header() (HTTP-Header, muss vor jeder Ausgabe stehen), http_response_code(), urlencode(), uniqid() / random_bytes(), hash(), number_format(), round() / floor() / ceil(), rand() / random_int().
