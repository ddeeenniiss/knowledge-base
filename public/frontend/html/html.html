Links

Links werden mit einem <a> Tag erstellt. Das Attribut href gibt den Link an.

target="" bestimmt dabei, wo der Link geöffnet wird. Standard ist immer _self (gleiches Fenster). _blank öffnet den Link in einem neuen Tab oder Fenster. _blank sollte immer mit rel="noopener" oder rel="noreferrer" kombiniert werden, um phishing Angriffe zu vermeiden. _parent öffnet das Dokument im übergeordneten Frame. Das ist dann relevant, wenn der Link in einem iframe eingebettet ist. Dann greift _parent auf das übergeordnete Dokument zu und wirkt quasi wie _self.
_top öffnet das Dokument im gesamten Fensterbereich. Das ist relevant bei mehreren Verschachtelungen von iframes. _top greift auf das oberste Dokument zu und öffnet den Link dort wie _self.

Überschriften

Ein <h1> bis <h6> Tag ist eine Überschrift die nach Wichtigkeit der Semantik geordnet ist. Eine h1 gibt es pro Seite nur einmal. h2 bis h6 können für Unterpunkte verwendet werden. Aber immer nachfolgend und nicht zB h2 auf h4, da dies die semantische Struktur der Seite durcheinander bringt. Suchmaschinen und Screenreader nutzen die Semantik, um die Struktur einer Seite zu verstehen.

Inline Elemente

Inline Elemente beginnen nicht in einer neuen Zeile und belegen nur so viel Platz wie nötig.

Beispiele sind span, a, i, img, textarea, var

Inline Elemente dürfen kein Blockelement enthalten. Browser würden automatisch das inline Element vorher schließen und das Blockelement danach öffnen. width und height funktionieren nicht. margin und padding funktionieren nicht korrekt.

span ist ein Inline Container, der für die Formatierung von Text innerhalb von anderen Elementen verwendet wird.

inline-block Elemente

width, height, margin und padding funktionieren vollständig

Buttons

Ein Button ist ein klickbares Element, das seine Funktion dann erhält, wenn man ihm eine Aktion zuweist.

Um einen Button zu deaktivieren, kann man das Attribut disabled hinzufügen. Eine Aktion wird durch JavaScript oder CSS ausgelöst zB durch onclick="alert('Button geklickt!')".

Ein Button hat mehrere type Attribute. Ein type="button" ist der Standardtyp, type="submit" sendet ein Formular ab, type="reset" setzt Formularfelder zurück.

Iframes - Anzeigen einer Webseite in einer Webseite

Eine iframe (inline frame) bindet ein Dokument in das aktuelle HTML Dokument ein.

Standardmäßig hat ein iframe einen Rand. src="" ist die Quelle des eingebundenen Dokuments. Höhe und Breite des iframes sollten entsprechend angepasst werden, damit der Inhalt vollständig angezeigt wird. title empfiehlt sich ebenso, damit Screenreader den Inhalt des iframes verstehen.

Iframe - Zieliframe für einen Link

Ein iframe kann als Zieliframe für einen Link verwendet werden. Das target Attribut des Links muss sich auf das name Attribut des iframes beziehen.

Semantische HTML Tags

Semantische HTML Tags sind Tags, die den Inhalt und die Struktur der Seite beschreiben. Sie sind für Suchmaschinenoptimierung (SEO), Barrierefreiheit und die Wartbarkeit des Codes wichtig.

section Tag

definiert einen Abschnitt einer Seite. Wird bei Modulen verwendet, da sie zusammen viele Abschnitte einer Seite bilden.

article Tag

definiert einen eigenständigen Inhalt einer Seite, der für sich allein sinnvoll ist. Ein article Tag kann innerhalb eines section Tags liegen.

header Tag

definiert den Header einer Seite oder eines Abschnitts. Enthält typischerweise Überschriften, Logo, Info zu Autoren

footer Tag

definiert den Footer einer Seite oder eines Abschnitts. Enthält typischerweise Urheberrechte, Kontaktinformationen, Sitemap

nav Tag

definiert eine Reihe von Navigationselementen innerhalb einer Seite.

aside Tag

definiert einen Inhalt, der sich vom Hauptinhalt der Seite unterscheidet. Typischerweise für Seitenleisten verwendet. Inhalt sollte indirekten Zusammenhang zum Hauptinhalt haben.

zugehörig gibt es das figcaption Tag, das eine Beschriftung für das figure Element darstellt.

definiert ein Bild in einer Seite. Bild ist Teil des Inhalts und benötigt keine Bildunterschrift.

canvas Tag

Das canvas Tag wird verwendet, um dynamische Grafiken und Animationen auf einer Website darzustellen. Grafiken können dynamisch mit JavaScript gezeichnet und aktualisiert werden.

Ein Canvas Element bekommt immer eine ID und eine Breite und Höhe.

Mit JavaScript kann man auf das Canvas Element zugreifen und darin Grafiken zeichnen. Alles in einem script Tag. 

    var canvas = document.getElementById("canvas");
    var ctx = canvas.getContext("2d");
    ctx.moveTo(0,0);
    ctx.lineTo(200,100);
    ctx.stroke();

Für einen Kreis wäre es:

    ctx.beginPath();
    ctx.arc(95, 50, 40, 0, 2 * Math.PI);
    ctx.stroke();

Das Canvas Element selbst lässt sich per css stylen. Aber alles was direkt per JavaScript gezeichnet wird, wird über den Kontext gesteuert. 

    ctx.font = "30px Arial";
    ctx.fillText = ("Hello World", 10, 50); //Inhalt und Position
    ctx.strokeText = ("Hello World", 10, 50); //Inhalt und Position nur umrandet

Es lassen sich auch Gradienten umsetzen.

    var gradient = ctx.createLinearGradient(0, 0, 200, 0);
    gradient.addColorStop(0, "red"); // Bei 0% rot
    gradient.addColorStop(1, "white"); // Bei 100% weiß

    ctx.fillStyle = gradient;
    ctx.fillRect(10, 10, 150, 80); // Rechteck mit Farbverlauf

Es können auch Bilder eingezeichnet werden.

    var img = document.getElementById("scream");
    ctx.drawImage(img, 10, 10); //Bild und Position

Web APIs

API steht für Application Programming Interface (Anwendungsprogrammierschnittstelle).

Eine Web API ist eine Schnittstelle, die es Webanwendungen ermöglicht, mit externen Diensten zu kommunizieren. Web APIs können die Funktionalität von Browsern erweitern, komplexe Funktionen vereinfachen und eine einfache Syntax für komplexen Code bereitstellen. Beispiele sind die Geolocation API, die Fetch API, die Web Storage API etc.

Eine der wichtigsten APIs sind folgende: (genaueres auf w3schools)

  1. Geolocation API: wird verwendet, um den aktuellen Standort des Benutzers zu ermitteln per Breiten und Längengrade.
  2. Drag and Drop API: wird verwendet, um die Nutzung von Drag and Drop Funktionen in Browsern zu ermöglichen.
  3. Web Storage API: wird verwendet, um Daten im Browser mit Key/Value Paaren zu speichern.
  4. Web Workers API: wird verwendet, um JavaScript im Hintergrund auszuführen, ohne die Seitenleistung zu beeinträchtigen. Benutzer können weiterhin alle gewünschten Aktionen ausführen, während der Web Worker im Hintergrund läuft.
  5. Server-Sent Events API: wird verwendet, um automatisch Aktualisierungen vom Server zu erhalten.
  6. Canvas API: wird verwendet, um 2D und 3D Grafiken in HTML Dokumenten zu zeichnen.

Die getCurrentPosition() Methode der Geolocation API wird verwendet, um den aktuellen Standort des Benutzers abzurufen. Die watchPosition() Methode verfolgt die Position des Benutzers kontinuierlich und ruft eine Callback-Funktion auf, wenn sich die Position ändert. Die clearWatch() Methode beendet die Verfolgung der Position des Benutzers, die mit watchPosition() gestartet wurde.

Wichtig ist dabei die Browserkompatibilität zu prüfen und eine robuste Fehlerbehandlung hinzuzufügen. Zudem sollte immer die Benutzerberechtigung eingeholt werden, bevor auf sensible Informationen wie Standortdaten zugegriffen wird.

Accessibility (Barrierefreiheit) / ARIA (Accessible Rich Internet Applications)

Für behinderte Menschen ist der PC/Laptop oft die einzige Möglichkeit einen Job auszuüben oder Kontakt zu anderen Menschen zu haben. Es müssen Lösungen für Menschen mit kontrastschwierigkeiten, gehörlose Menschen, sehbehinderte Menschen und körperlich eingeschränkte Menschen geschafft werden. Die komplette Software sollte über die Tastatur bedienbar sein.

Accessivility Tree

Browser haben neben dem DOM Tree auch einen Accessibility Tree, der Informationen über die Barrierefreiheit des Inhalt enthält. Dieser kann in den Devtools unter Elements -> Accessibility eingesehen werden.

aria-hidden="true"

Über aria-hidden="true" kann man ein Element und all seine Kinder aus dem Accessibility Tree ausblenden. Der Screenreader liest das also nicht vor. Wird dann verwendet, wenn ein Element redundant ist, also wenn es bereits einen Text gibt, der dasselbe aussagt. Auch unsichtbare Elemente sollten damit versehen werden.

ACHTUNG: Nicht auf fokussierbaren Elementen verwenden.

Es ist unnötig, dass Attribut zu setzen, wenn ein HTML hidden Attribut verwendet wird und ebenso wenn das Element mit display: none; oder visibility: hidden; versehen ist, da diese Elemente automatisch aus dem Accessibility Tree entfernt werden.

values: true, false, undefined (default)

Hier würde der Screenreader das Icon nicht vorlesen, da es mit aria-hidden="true" ausgeblendet ist. Er würde nun vorlesen "Suche Button". Wenn Text und Icon dasselbe aussagen, dann sollte das Icon nicht vorgelesen werden.

aria-current: page

wird verwendet, um dem Screenreader mitzuteilen, dass es sich um die aktuelle Seite handelt.

aria-label="Beschreibung / Anweisung"

aria-label wird verwendet, um eine Beschreibung oder Anweisung für ein Element zu geben, die vom Screenreader vorgelesen wird. Es wird im Accessibility Tree als Name des Elements angegeben.

verwendet wird es, wenn ein Element keine sichtbare Beschriftung hat, z.B. Icon Buttons, Schließen Buttons, SVG, Bilder, Hintergründe

aria-labelledby=""

aria-labelledby verweist auf ein anderes Element, das als Label für das aktuelle Element dient. Das andere Element muss eine id haben, die im aria-labelledby referenziert wird. aria-labelledby ist vorzuziehen gegenüber aria-label, da es die Beziehung zwischen den Elementen im Accessibility Tree herstellt und damit die Struktur der Seite besser verständlich macht. Zudem überschreibt es aria-label, da es vorgezogen wird, wenn beide vorhanden sind. Anwendung bei Dialogen, Formulargruppen und Regionen. 

      
Bewerbungsformular

aira-describedby=""

aria-describedby verweist auf ein anderes Element, das als Beschreibung für das aktuelle Element dient. Das andere Element muss eine id haben, die im aria-describedby referenziert wird. Es ersetzt kein aria-label und dient nur als Zusatzinformation. 

      
Bitte füllen Sie alle Pflichtfelder aus.

aria-live=""

aria-live gibt an, ob sich der Inhalt eines Elements dynamisch ändert. Es wird verwendet, um Screenreader zu informieren, dass sich der Inhalt eines Elements verändert hat und der Screenreader den Inhalt sofort vorlesen soll. Es gibt drei Werte: off (default), polite und assertive. Polite wird dann vorgelesen, wenn gerade nichts anderes vorgelesen wird. Assertive wird sofort vorgelesen, auch wenn etwas anderes vorgelesen wurde.

aria-expanded=""

aria-expanded wird für aufklappbare Elemente verwendet. Es gibt an, ob ein Element aufgeklappt (true) oder zugeklappt (false) ist.

aria-controls=""

aria-controls verweist auf ein anderes Element, das von diesem Element kontrolliert wird. Das andere Element muss eine id haben, die im aria-controls referenziert wird.

role

HTML hat bereits eine eingebaute Rolle (role) für jedes Element. Ein button Tag hat z.B. die Rolle "button". Problem ist nun bei div, span, denn diese haben die Rolle "generic" und sagen dem Screenreader nichts über die Funktion des Elements aus. Mit role kann man die Rolle eines Elements ändern, damit der Screenreader die Funktion des Elements besser verstehen kann. Es sollte immer die sematisch passende Rolle gewählt werden.

Sollte vor allem bei eigenen Komponenten verwendet werden wie Tabs, Accordions, Modals, Dropdowns, Tooltips. Ebenso bei Fehlerausgaben, z.B bei Validierungen.

Wenn es bereits ein natives HTML Element gibt, das die gewünschte Rolle hat, sollte dieses verwendet werden, da es stabiler und weniger fehleranfällig ist.
